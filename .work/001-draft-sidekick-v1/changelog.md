# 001-draft-sidekick-v1

## What changed

Draft Sidekick v1 ships end to end — the full PRD (`prd/draft-sidekick/prd.md`, FR-1 through FR-11), no narrowing. A local, free-to-run web app (npm workspaces: `packages/shared`/`server`/`web`, Express + SSE backend, React frontend) that attaches to a live Sleeper draft, replaces manual board bookkeeping with automatic sync, and surfaces need-aware, survival-projected pick recommendations. Final state: 42 test files / 671 tests, lint and typecheck clean, production build clean (`dist/assets/index-D-qxXAQs.js` 187.19 kB / gzip 57.72 kB). The reviewed feature diff (`spec_review`'s first pass) was 165 files / ~46.8k insertions.

**Attach, sync, and recovery (FR-1, FR-2, FR-3)**
- Attach by pasted Sleeper draft URL/ID (league or mock); teams/owners render before any insight does; manual slot picker when the seat can't be auto-detected from `draft_order`; classified, retryable errors on a bad ID or unreachable API with input preserved; one draft per running instance, with a second concurrent instance sharing (and backing off within) the same per-IP request budget.
- Stateless full-refetch polling (default 1 s, ≤120 req/min) — never incremental diffs. New picks reflect in every view, the pick feed, and rosters within 3 s; traded picks attribute to their current owner; mid-draft attach rebuilds complete state from the pick list alone.
- Degraded detection (failed/malformed/inconsistent poll) with continuous retry and automatic full re-ingest on the next good poll, plus a one-click **Re-sync** (≤5 s). Unmatched drafted players show under their raw Sleeper name with a visible warning. Any insight computed from a superseded board is marked recomputing, never presented as current.

**Rankings and rosters (FR-4, FR-5)**
- Pre-draft check: FantasyPros half-PPR ECR + Fantasy Football Calculator ADP snapshots fetched once per attach and held immutable for the draft; snapshot age/staleness warning (24 h default); ID-crosswalk matching (dynastyprocess `db_playerids.csv`) with normalized-name fallback; unmatched-entry and matched-without-ADP lists; scoring-format-mismatch warning; explicit "no rankings loaded" degraded mode (board/roster/pick-feed keep running, candidate list/survival/recommendations disabled) when the ECR fetch fails.
- Roster panel and every downstream need vector read team count, slot structure, and scoring settings from the draft/league API — no hardcoded league shape; non-default leagues (3 WR, 12 teams) work through the same code path. K/DST slots are tracked on rosters but excluded from prediction math.

**Opponents, survival, and the recommendation (FR-6, FR-7, FR-8, FR-9, FR-10)**
- Opponent panel: the window (snake- and trade-aware) of picks before your next turn, each team's unfilled slots/need vector/remaining picks, and normalized most-likely-position(s) with ADP-drawn example players — position-confidence and player-example are visually and structurally distinct, never presented as equally certain.
- Within-draft tendency profiles (average reach, need-adherence, positional counts vs. league baseline; neutral priors and an early-profile label until 3 picks) bend each team's sampling distribution; discarded on detach/new attach.
- Monte Carlo survival simulation (2000 runs by default) over the window, seeded from the board itself so an unchanged board reproduces identical percentages (SC-2's stability guardrail holds structurally, not just on average); retains full per-run survivor data, not just marginal percentages. Likely-gone/coin-flip/likely-available bands; suppressed with no next pick; K/DST saturation rule keeps late-round K/DST demand from inflating skill-position scarcity; recomputes within 5 s of a burst's final pick (debounced to one recompute per burst, not one per pick).
- Candidate list: top 8 (configurable) in raw ECR order — the measured QB-vs-ADP skew ships undisclosed-but-unadjusted, visible only via the per-row ADP column, per the PRD's non-goal against blending ECR. Position filter, including a K/DST-only ECR/ADP-order variant. Exactly one highlighted recommendation, placed by a two-pick lookahead that compares positional plans (current + next pick, restricted to positions with an unfilled slot) scored by ECR rank now plus Monte-Carlo-expected ECR rank next; one-line reason by precedence (plan/survival, need, value, best-available), with too-close-to-call and plan-too-close statements merged into a single line rather than shown twice.

**Player game logs (FR-11)**
- One click from any candidate row, pick-feed entry, or roster entry opens a player card without leaving the draft screen: per-game stat line (position-appropriate columns), season tabs, fantasy points recomputed from the attached league's own scoring settings (not the source data's generic column), and an explicit no-data state for players with no NFL history.
- `npm run prep:nflverse`: an offline script, no part of the live server's request path, that downloads and slims nflverse player-stats and play-by-play data (deriving "longest play" per game) into `data/cache/gamelogs.json`, joined to Sleeper ids via the same crosswalk FR-4 uses.

**Cross-cutting**
- Every numeric threshold named 🔶 AS-N in the PRD (poll cadence, latency budgets, candidate-list length, survival bands, staleness window, API budget, near-tie thresholds, etc. — 27 keys total) lives in `packages/shared/src/config/parameters.ts` and is overridable via `config.local.json`, never hardcoded.
- Per-pick sync lag and per-burst insight-refresh latency are instrumented (`/api/debug/metrics` + structured log lines) specifically so the PRD §14 mock-rehearsal protocol can judge the SC-1/SC-2 p95 targets live.

## Gate outcomes

**spec_review — pass, after 1 repair.** First pass failed on two blocking issues: AC-50's K/DST ADP-order fallback was unreachable in production (nothing fed the fallback branch — a cheat sheet without K/DST rendered an empty filter instead of falling back to ADP order), and AC-27 compared the draft's coarse scoring *label* where the criterion requires comparing the league's actual scoring *settings* (the codebase's own AC-64 path already proved the label unreliable). Repair (12 files, real end-to-end fixtures, no scope creep) made both paths real; re-verified pass: `655/655` tests, both fixed ACs driven through the real ingest pipeline with discriminating fixtures (an internal control proved the new assertions couldn't have passed pre-repair), zero regression on the surrounding ACs.

**code_review — pass, after 1 repair.** First pass failed on four blocking issues: (B1) five literal NUL bytes used as hash separators in `simulation/montecarlo.ts` made the file read as binary data to `grep`/`file`, hiding it from search; (B2) no error boundary anywhere — a throwing recompute cascade, a rejected route promise, or an uncaught exception reached the runtime and killed the process; (B3) attach's three third-party fetches (crosswalk/ECR/ADP) had a timeout signal plumbed but never constructed, so a slow host could hang attach indefinitely; (B4) a prototype-shaped player id (e.g. `constructor`, `__proto__`) crashed the game-log endpoint with a 500 and a stack trace instead of AC-65's no-data card. Repair fixed all four; re-verification used mutation tests (revert each fix, confirm the covering suite goes red) rather than trusting green tests at face value — e.g. reverting B2's try/catch reproduced the exact crash trace the original finding described; reverting B4's guard reproduced the exact 500. Final: `671/671` tests, no regression, prior 14 non-blocking observations re-confirmed unaffected plus 2 new non-blocking notes (N15, N16 — see below).

**qa — pass, first attempt.** Real server (real `index.ts` wiring, no shortcuts) driven over HTTP/SSE and the built frontend against the T15 fixture bundles, the real nflverse cache, and live Sleeper error paths (a joinable live mock wasn't obtainable — Sleeper purges completed mocks server-side and joining a new one needs account sign-in, out of scope for the agent; recorded as the stated fallback). Headline evidence: burst-refresh latency sits at ~400 ms against the 5000 ms budget (12x margin) at a 150-pick board; poll cadence measured at 59 req/60s against the 120 budget, with a real second instance falling to 41/39 req/60s combined under load; a `kill -9` mid-draft restart produced a byte-identical `AppStateSnapshot` versus a live-watched process; three independently injected faults (thrown timer callback, unhandled rejection, thrown recompute) were each contained — same pid, board marked degraded with a named reason, cleared on the next good cascade; AC-64's league-scoring differential proven by driving the *same* game through two different scoring dicts and getting the exact predicted point delta. Three non-blocking findings recorded (below); none blocked the verdict.

## Flagged deviations / spec defects (recorded during review)

- **AC-55 (FR-10 plan scoring), read literally, makes the "plan/survival" highlight reason permanently unreachable.** The plan score is `term1(now) + term2(next)`; if `term2` is computed independently of which player `term1` already spends, the sum is separable across positions and `argmin` always resolves to the plain best-available-at-a-needed-position pick — exactly AC-51's "need" reason, verbatim, leaving "plan/survival" as dead code and FR-10's own "optimizes jointly" headline false of its own implementation. Fixed by excluding the `term1` player from the `term2` lookup, but only when the plan's now-position and next-position are the same (cross-position plans are bit-for-bit unaffected). Flagged explicitly to the orchestrator in dev-notes as a deliberate, argued departure from AC-55's literal method clause, not an oversight (`dev-notes-T8.md` §1).
- **design.md §T7's `remainingPicksInWindowIncludingThis` (the K/DST saturation rule), read literally, breaks survival math entirely** — within two rounds every seat has an open K and DST slot inside a short window, so the saturation check fires for everyone and no simulated pick ever consumes a skill player, making every candidate show 100% survival. Implemented as draft-wide remaining picks instead, matching both PRD FR-8's own wording ("remaining picks", no window qualifier) and spec.md AC-47 exactly (`dev-notes-T7.md` §4).
- spec_review's first (failing) pass additionally recorded "five accepted deviations" and other non-blocking spec defects in aggregate as part of its evidence; that verdict file was superseded when the repair was re-reviewed and only the second (passing) verdict's text survives in `review-spec.md` today. The two items above are the substantive instances independently traceable through dev-notes; they were accepted as correct departures from literal spec/design text, not left as open issues.
- Both of spec_review's own blocking issues (AC-50 unreachable fallback, AC-27 label-vs-settings) were self-flagged by developers *before* the gate caught them — T8 and T10's dev-notes both call out "AC-50's ADP fallback is implemented but currently unreachable through T3's output" as a forward-reference to the exact defect the repair later fixed.

## Known non-blocking findings

- **Quiet recovery leaves panels flagged.** When an automatic degraded→healthy recovery completes with no new pick to react to, the board version bumps without triggering a recompute, so the sync indicator reads recomputing and every panel stays dimmed until the next pick lands or Re-sync is pressed by hand. Nothing stale is ever shown as current (AC-21 holds) and one click clears it, but a user on the clock at that exact moment sees dimmed panels at the worst time. Backlog candidate.
- **"No rankings loaded" mode over-badges the pick feed.** With no ECR snapshot loaded, every single pick renders its own "Unmatched" badge and warning note (40 picks → 40 notes) even though the candidate list already states the one real cause once. Each note is individually accurate; the aggregate is noise. Cosmetic, and only in a rare/degraded mode.
- **`body` has no background color** (`rgba(0,0,0,0)`), so scrolling past the app container exposes the browser's white default underneath the dark UI. Cosmetic.
- Code review's final pass stands on 16 non-blocking observations total (N1–N16 — the original 14 plus two noted during the repair's re-review: `settleBurst`'s try/catch doesn't cover the broadcast call itself, and the new Express error boundary logs via bare `console.error` rather than the shared observability sink); full detail in `.work/001-draft-sidekick-v1/review-code.md`.

## Validation status

The automated gates are green: T15's 150-pick end-to-end replay (traded pick, a 3+ pick burst, one unmatched player, the user drafting on schedule throughout) converges to the fixture's exact true end state with zero unhandled exceptions, and qa re-derived the same real-server behavior independently over HTTP/SSE.

Still ahead, and explicitly out of this pipeline's scope per spec.md and PRD §14: **live Sleeper mock-draft rehearsals.** The PRD's real-draft readiness gate is ≥3 full live mock rehearsals with zero non-converging board states, plus a manually-kept post-draft SC-3/SC-4 checklist — both are live-judgment activities that this repo's spec/code/qa gates don't represent by design (no automated suite can join a live Sleeper mock or judge felt-informedness). This is the user's runway before a real draft, not a defect in what shipped.
